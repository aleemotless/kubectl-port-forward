    Networking
    
    
    kubectl apply -f service.ymlServices
    
    
    A stable name and virtual IP in front of Pods that come and go. No process runs it. It is rules in every node's kernel.
    
    
      
      
    • name nginx-svc
      • 
      
    • selector app=nginx
      • 
      
    • port 80 → 80
      • 
      
    • ClusterIP 10.96.45.120
      • 
    
    
  
    

    


    
  
    
    
    What actually happens
    
    
    The packet never visits a "service"
    
    
    kube-proxy watches EndpointSlices and writes NAT rules. The kernel rewrites the destination from the ClusterIP to a Pod IP.

    Each type wraps the one before it
    
    
    NodePort is ClusterIP plus a port on every node. LoadBalancer is NodePort plus a real cloud load balancer.

    Networking
    
    
    kubectl apply -f ingress/Ingress
    
    
    One HTTP entry point for the whole cluster. Routes by host and path to Services. The Ingress object is only a rule list. A controller you install does the work.
    
    
      
      
    • Ingress my-ingress
      • 
      
    • path / → my-app:80
      • 
      
    • controller ingress-nginx
      • 
      
    • cluster kind dev-cluster
      • 
    
    
  
    

    


    
  
    
    
    The problem
    
    
    One load balancer per app gets expensive
    
    
    LoadBalancer Services work at layer 4: one IP each, no idea about URLs. Ingress puts one layer 7 router in front of everything.
    
  
    
  
    
    
    
      
    
    
    
    
    
    
      
    
        
        
      
    
    
    
  
    

    


    
  
    
    
    Controllers
    
    
    An object does nothing until a controller watches it
    
    
    A controller is a loop: watch the desired state, compare with reality, act, repeat. kube-controller-manager runs the built-in ones. There is no Ingress controller among them.

    Under the hood
    
    
    A Go controller driving nginx
    
    
    Rule changes rewrite nginx.conf and reload. Pod changes skip the reload: the new IPs go straight into a Lua balancer.
    
  
    
  
    
    
    
      
    
    
    
    
      
      
      
      
    
    
    
    
  
    
  
      
    
    • nginx sends traffic straight to Pod IPs. The Service is only used to look up endpoints, so kube-proxy is skipped.
      • 
    
    • A validating webhook runs nginx -t on your Ingress before the API server stores it. Broken config gets rejected at apply time.
      • 
  
    

    


    
  
    
    
    Routing rules
    
    
    Which rule wins?
    
    
    Host first, then the longest matching path. Prefix matches whole path segments: /api matches /api/users but not /apifoo.
    
  
    
  
    
    
    
      
      
      
      
      
      
    
    
    
    
    
    Pick a request.
    
  
    

    


    
  
    
    
    Also
    
    
    Worth knowing
    
  
    
  
    
    
    IngressClassingressClassName: nginx
    Says which controller owns the Ingress. Without it, the kind manifest still works because it sets --watch-ingress-without-class.
    
    
    TLStls: [{hosts, secretName}]
    nginx terminates HTTPS using a kubernetes.io/tls Secret, then talks HTTP to Pods.
    
    
    Annotationsnginx.ingress.kubernetes.io/rewrite-target
    Controller-specific options: rewrites, timeouts, body size, rate limits.
    
    
    No matchdefaultBackend
    Requests no rule matches get nginx's 404, or the default backend if you set one.
    
    
    HTTP onlylayer 7
    Ingress routes HTTP/HTTPS. Plain TCP/UDP still needs a NodePort or LoadBalancer Service.
    
    
    ingress-nginx is retiredGateway API
    Upstream maintenance ended in March 2026. Fine for learning; for new setups use Gateway API (HTTPRoute) or another controller.

      Anatomy of the command
      
    
      The command, part by part
      
  
      
  
      
    
      
      kubectl port-forward
      -n default
      pod/nginx-pod1
      8080:80
      --address 127.0.0.1
    
      
    
        
      
      • kubectl port-forward
        Runs in the foreground. Ctrl-C closes the tunnel.
        • 
      
      • -n default
        Namespace. Defaults to your current context's.
        • 
      
      • pod/nginx-pod1
        Target. deploy/, sts/, svc/ also work, but resolve to one Pod.
        • 
      
      • 8080 local port
        On your machine. :80 picks a random one. Add more pairs for more ports.
        • 
      
      • 80 remote port
        Port inside the Pod. For svc/, the Service port.
        • 
      
      • --address
        Default localhost: only you. 0.0.0.0: your whole network.
        • 
    
      
  
      

      



      
  
      
    
      
      
      Inside the pipe
      
      
      One tunnel, many streams
      
      
      One connection to the API server. Each local TCP connection adds a data + error stream pair inside it, tagged with the port and a request ID.

        Troubleshooting
        
    
        The errors you'll actually see
        
  
        
  
        
    
        
      
        Local port taken
        

        error: unable to listen on any of the requested ports: [{8080 80}]
        
      
        Fix: use another local port, or find the owner: lsof -i :8080.
        
    
        
    
        
      
        Nothing listening in the Pod
        

        failed to connect to localhost:80 inside namespace …: connect: connection refused
        
      
        Fix: wrong remote port, or the app isn't up. Check kubectl logs.
        
    
        
    
        
      
        Forbidden
        

        User "dev" cannot create resource "pods/portforward" in the namespace "default"
        
      
        Fix: grant the Role below. Check with kubectl auth can-i create pods/portforward.
        
    
        
    
        
      
        Pod went away
        

        error: lost connection to pod
        
      
        Fix: run the command again. It never reconnects by itself.
        
    
        
  
        
  
        

        apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: port-forwarder
  namespace: default
rules:
  - apiGroups: [""]
    resources: ["pods"]
    verbs: ["get", "list"]
  - apiGroups: [""]
    resources: ["pods/portforward"]
    verbs: ["create"]
